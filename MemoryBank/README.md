# MemoryBank - Project Knowledge Repository

## Purpose

The MemoryBank serves as the **persistent memory and knowledge repository** for the Slay Drip Digital Wardrobe project. This folder contains comprehensive documentation that AI agents, developers, and team members should consult to understand the current state of the project, recent changes, and implementation details.

## 🎯 **How to Use MemoryBank**

### For AI Agents (Claude, Cursor, Gemini, etc.)
- **ALWAYS** check MemoryBank documents before making significant changes
- Use these documents to understand project context and maintain consistency
- Reference recent changes to avoid duplicating work or breaking existing functionality
- Consult testing documentation before modifying test-related code

### For Developers
- Review project overview when onboarding to the project
- Check recent changes to stay up-to-date with latest implementations
- Refer to testing framework documentation for test writing and execution
- Use these documents as authoritative source for project architecture decisions

### For Project Management
- Reference implementation summaries for status updates
- Use testing achievements for quality assurance reporting
- Consult project overview for technical architecture discussions

## 🔄 **Maintenance Guidelines**

### When to Update MemoryBank

1. **Major Feature Implementations**: Document new features, architecture changes, or significant functionality additions
2. **Technology Stack Changes**: Record updates to frameworks, libraries, or development tools
3. **Testing Framework Modifications**: Update testing documentation when adding new test types or changing test structure
4. **Deployment and Infrastructure Changes**: Document changes to deployment processes, CI/CD, or infrastructure
5. **Performance Optimizations**: Record significant performance improvements or architectural optimizations
6. **Bug Fixes and Problem Solutions**: Document complex problem-solving and resolution patterns

### Update Process

1. **Create or Update Documents**: Add new information to existing documents or create new documents as needed
2. **Update Recent Changes**: Always update `recent-changes.md` with latest modifications
3. **Cross-Reference**: Ensure documents reference each other appropriately
4. **Validate Links**: Check that all internal links and references are working
5. **Review Consistency**: Ensure information is consistent across all documents

### Document Standards

- **Use Clear Headings**: Structure documents with clear, hierarchical headings
- **Include Examples**: Provide code examples, screenshots, or practical demonstrations
- **Date Entries**: Include dates for all changes and implementations
- **Be Specific**: Include technical details, command examples, and specific implementation notes
- **Maintain Context**: Explain not just what was done, but why and how it impacts the project

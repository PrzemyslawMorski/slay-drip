## User story

Requirement served: none names local stack tooling (gap, see the spec). It enables the local-run rule in CLAUDE.md.

```gherkin
Feature: Playwright takes ports from the stack file and starts its own server
  As a considered dresser
  I want the whole app to run locally in its own worktree
  So that I and the agents can test it end to end without clashes
```

The Playwright container and its run are S1-07.07 and S1-07.08. This ticket only changes port handling: playwright.config.ts, running inside that container, reads in-network baseURL and API URLs from stack.json (host-side ports stay for people), sets reuseExistingServer to false, fails fast when the stack file is missing, and the support code signs in the synthetic test user from the realm. The stack-lifecycle project is left unchanged (open decision). Governing design: [S1-08](S1-08-local-stack.md), [ADR-0016](../adr/0016-per-worktree-local-stack.md).

## Acceptance criteria

```gherkin
Scenario: Playwright runs against the worktree's own stack with a test user
  Given the stack of this worktree is running
  When I run the Playwright acceptance suite
  Then the suite uses the web and API ports from this worktree's stack file
  And a synthetic test user signs in through the local Keycloak
```

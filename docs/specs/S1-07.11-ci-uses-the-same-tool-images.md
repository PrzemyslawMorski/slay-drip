## User story

Requirement served: none names containerised tooling. It enables F7 (through S1-06) and the local-run rule in CLAUDE.md. See the spec's Problem section.

```gherkin
Feature: CI uses the same tooling images as development
  As a considered dresser
  I want CI to run the same pinned tool images as my machine
  So that a green local run means a green CI run
```

`.github/workflows/backend-ci.yml` and `frontend-ci.yml` install tools with setup actions today. The owner decided on 2026-11-02 that CI runs the same compose tool images as local development, headless (ADR-0014). This ticket waits only on its dependencies. Governing design: [S1-07](S1-07-containerised-dev-tooling.md). Spec: [S1-07](S1-07-containerised-dev-tooling.md).

## Acceptance criteria

```gherkin
Scenario: Each toolchain runs in a container with no host install beyond Docker
  Given a CI runner with only Docker and Compose v2 available
  When a CI job runs a Go, Node or Python check through its compose tool service
  Then the check runs in the same pinned image as on a developer machine
  And no setup action installs Go, Node or Python on the runner
```

- **Role:** `infra-engineer` (see `.claude/skills/tickets-from-spec/references/roles.md`)
- **Goal:** Both CI workflows run their checks through the compose tool services, with actions pinned by SHA as they are now.

- **Files to change:**
  - `.github/workflows/backend-ci.yml`, run the checks through the `go` service
  - `.github/workflows/frontend-ci.yml`, run the checks through the `node` service
- **Do not touch:** `compose.yaml` and the tool images (S1-07.06 to S1-07.10). Do not change permissions, triggers or secrets. Never read, search, print or create `.env` files.
- **Covers scenarios:** `Each toolchain runs in a container with no host install beyond Docker`. This is a ticket-level restatement of the spec scenario "Each toolchain runs in a container with no host install beyond Docker" for this layer; it adds no behaviour to the spec.
- **Done when:** both workflows pass on a pull request, with the same commands as the local guide. Playwright runs headless in CI.
- **Out of scope:** Production image build or deploy.
- **Open questions:** The Docker layer cache approach for CI is not decided; propose one in the PR. CI mode (same images, headless) is decided.

Definition of done note: no AI, consent, retention or body data is touched, and no UI is changed, so those two lines do not apply.

No spec scenario covers CI. The scenario in this ticket restates the host-install rule for CI runners and is unit-level; it is not an addition to the spec.

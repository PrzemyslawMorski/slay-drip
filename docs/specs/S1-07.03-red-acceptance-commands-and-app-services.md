## User story

Requirement served: none names containerised tooling. It enables F7 (through S1-06) and the local-run rule in CLAUDE.md. See the spec's Problem section.

```gherkin
Feature: Host-neutral commands and app services, acceptance tests
  As a considered dresser
  I want executable checks that every documented command is the same on every host and that the app runs from compose
  So that the compose app services start from failing scenarios
```

Static checks on the documented commands and on the `api` and `web` service definitions. The live check that the API answers on 8080 belongs to S1-07.10. Governing design: [S1-07](S1-07-containerised-dev-tooling.md). Spec: [S1-07](S1-07-containerised-dev-tooling.md).

## Acceptance criteria

```gherkin
Scenario: The same commands work on Windows, macOS and Linux hosts
  Given the documented tool commands
  When they are read for each host
  Then every command starts with "docker compose" and uses no shell syntax that differs by host
  And no command needs a Makefile, a shell script or a PowerShell script

Scenario: The API and frontend run from compose
  Given the compose file
  When a developer starts the "api" and "web" services
  Then the API answers GET /healthz on 127.0.0.1:8080 and the frontend is served on localhost:5173
  And both reach the stand-ins through the same config keys as production
```

## User story

Requirement served: none names containerised tooling. It enables F7 (through S1-06) and the local-run rule in CLAUDE.md. See the spec's Problem section.

```gherkin
Feature: Frontend tooling in a container
  As a considered dresser
  I want typecheck, lint, format check and unit tests to run in a Node container
  So that no Node install is needed on my machine
```

Adds the `node` tool service on the pinned Playwright base image, so one image serves both the frontend checks and the browser tests (ADR-0014). The image tag must match `@playwright/test` in `frontend/package.json`. Dependencies install inside the container, not from the host. Where `node_modules` lives is decided by the S1-07.01 note. Governing design: [S1-07](S1-07-containerised-dev-tooling.md). Spec: [S1-07](S1-07-containerised-dev-tooling.md).

## Acceptance criteria

```gherkin
Scenario: The same commands work on Windows, macOS and Linux hosts
  Given the documented tool commands
  When they are read for each host
  Then every command starts with "docker compose" and uses no shell syntax that differs by host
  And no command needs a Makefile, a shell script or a PowerShell script

Scenario: Frontend checks run in the Node container
  Given the Node tool service with the frontend dependencies installed inside it
  When a developer runs typecheck, lint, format check and unit tests through it
  Then each runs in the container and reports its result
  And no node_modules folder from the host is used
```

## User story

```gherkin
Feature: A developer runs the MCP journey from a sample client
  As a considered dresser
  I want a developer to run the whole journey from a small client
  So that the elicitation pattern and the MCP tools can be seen working together
```

Context: a Python sample in `examples/mcp-elicitation/`, using the standard library only. It signs a synthetic persona in through Keycloak with PKCE, runs the journey against the local stack, and answers the category question. It keeps tokens in memory only and never logs them. Status is Blocked until the elicitation tickets, the outfit tools and the upload tool exist.

## Acceptance criteria

```gherkin
Scenario: A signed-in person uploads sample items, creates an outfit and views it
  Given a signed-in synthetic persona with wardrobe consent and an empty wardrobe
  When the client uploads three sample items, answering the category question if it is asked, and then creates a named outfit from two of them
  Then each upload returns the new item's ID
  And the outfit is saved with the name and the two chosen item IDs
  And listing the outfits shows that outfit with its name and those item IDs
```

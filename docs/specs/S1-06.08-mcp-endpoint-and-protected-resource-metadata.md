## User story

```gherkin
Feature: MCP endpoint is served by the API and closed to anonymous callers
  As a considered dresser
  I want the API to offer an MCP endpoint that checks my sign-in token
  So that an AI client can connect to the API, and only a signed-in person can use it
```

Context: ADR-0012 chooses the official Go SDK, Streamable HTTP in stateless mode, mounted at `/mcp` on the existing mux, wrapped by `auth.RequireBearerToken` with the existing `auth.Verifier`. The API also serves protected resource metadata. This ticket adds the pin for the SDK.

## Acceptance criteria

```gherkin
Scenario: A request without a valid token is refused
  Given no token, an expired token, or a token for another audience
  When the client calls any MCP tool
  Then the call returns 401 with a WWW-Authenticate header and no detail about why it failed

Scenario: Protected Resource Metadata is published
  Given an MCP client that has no token
  When it requests the protected resource metadata
  Then the response names the API resource and its authorization server
```

## Notes

**Agent brief**

- **Role:** `backend-engineer` (see `.claude/skills/tickets-from-spec/references/roles.md`)
- **Goal:** `/mcp` and `/.well-known/oauth-protected-resource` are served by the API, `/mcp` rejects requests without a valid token with 401, and the metadata names the API resource and its authorization server.
- **Read first:** [ADR-0012](../adr/0012-mcp-server-transport-and-auth.md), [ADR-0010](../adr/0010-identity-provider-keycloak.md), [backend ruleset](../code-review/backend-ruleset.md) (BE-41, BE-47), [security guide](../security.md) §5.
- **Files to change:**
  - `backend/go.mod`, pin `github.com/modelcontextprotocol/go-sdk` at a v1.x release
  - `backend/go.sum`, the checksums for that pin
  - `backend/internal/mcp/server.go`, new package: the MCP server, the stateless Streamable HTTP handler and the token verifier that wraps `auth.Verifier`
  - `backend/internal/server/server.go`, mount `/mcp` and the metadata path on the existing mux
  - `backend/internal/server/mcp_routes_test.go`, route tests for the two scenarios
- **Do not touch:** the realm file (S1-06.02), the tools (S1-06.09 and later), the rate limiter and the gate.
- **Covers scenarios:** `A request without a valid token is refused`; `Protected Resource Metadata is published`.
- **Done when:** `go test ./...` and `golangci-lint run` in `backend/` pass; `govulncheck` is clean (ADR-0007); the route tests run without a build tag (BE-24). Unit tests cover the expired-token and wrong-audience cases from the first scenario's Given line, using `backend/internal/auth/authtest`.
- **Out of scope:** tool registration, the consent gate, the age gate and rate limiting, each in its own ticket.
- **Open questions:** None. The stateless choice follows ADR-0012. If an older MCP client cannot negotiate with it, the ADR's revisit section applies, and that is a new decision.

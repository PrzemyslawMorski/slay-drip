## User story

Requirement served: none names containerised tooling. It enables F7 (through S1-06) and the local-run rule in CLAUDE.md. See the spec's Problem section.

```gherkin
Feature: Browser acceptance tests in a container
  As a considered dresser
  I want `npm run test:acceptance` to run in the Playwright container
  So that the browser tests need no browser install on my machine
```

The owner decided on 2026-11-02 that stack setup stays on the host: the Playwright container gets no Docker socket and no Docker CLI, and the test process never runs `docker compose`. One documented host command starts or stops the stack, and the containerised run only talks to the running stack, headless. The stack-lifecycle scenarios are rewritten (S1-07.15) to check a running stack, so the container run covers the whole acceptance suite. Governing design: [S1-07](S1-07-containerised-dev-tooling.md). Spec: [S1-07](S1-07-containerised-dev-tooling.md).

## Acceptance criteria

```gherkin
Scenario: Playwright acceptance tests run in the Playwright container
  Given the Node tool service with the Playwright browsers
  When a developer runs "npm run test:acceptance" through it
  Then the acceptance scenarios run in the container against the stack
  And the result is reported as it is on a host install

Scenario: The local identity provider starts beside PostgreSQL and the S3 stand-in
  Given the local stack was started on the host with "docker compose up -d"
  When I check the running services
  Then the keycloak service is running and reports healthy
  And keycloak listens on 127.0.0.1 only
  And the database and object-storage services are still running
  And keycloak has no named volume
```

## Notes

**Agent brief**

- **Role:** `infra-engineer` (see `.claude/skills/tickets-from-spec/references/roles.md`)
- **Goal:** With the stack started on the host, `docker compose run --rm node npm run test:acceptance` runs the whole acceptance suite headless in the container against the running stack.
- **Read first:** [ADR-0003](../adr/0003-gherkin-acceptance-tests-with-playwright.md), [ADR-0010](../adr/0010-identity-provider-keycloak.md), the S1-07.01 discovery note, `frontend/playwright.config.ts` (read only)
- **Files to change:**
  - `compose.yaml`, the Playwright run: network to the running stack, headless setting, shared memory size; no Docker socket mount
- **Do not touch:** `frontend/playwright.config.ts` and the test support files. If the config needs a change, stop and report: no role owns that file. Never read, search, print or create `.env` files.
- **Covers scenarios:** `Playwright acceptance tests run in the Playwright container`; `The local identity provider starts beside PostgreSQL and the S3 stand-in`
- **Done when:** scenario `Playwright acceptance tests run in the Playwright container` passes by reading the definition, and a live run passes: the stack is started with the documented host command (`docker compose up -d`), then `docker compose run --rm node npm run test:acceptance` passes headless, the whole suite with no project excluded and no `--no-deps`. The compose definition has no `docker.sock` mount and the image has no Docker CLI. The PR shows the run and the Playwright image tag.
- **Out of scope:** Image creation (S1-07.07). CI wiring (S1-07.11). Rewriting the stack-lifecycle scenarios (S1-07.15).
- **Open questions:** None for the stack scenarios: decided by the owner (rewritten, S1-07.15). If the run needs a change to `frontend/playwright.config.ts`, stop and report: no role owns that file.

Definition of done note: no AI, consent, retention or body data is touched, and no UI is changed, so those two lines do not apply.

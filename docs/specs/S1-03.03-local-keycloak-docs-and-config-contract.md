## User story

Requirement served: the Session 1 walking skeleton row, so that developers can run the sign-up path on their machine.

```gherkin
Feature: Local identity provider documentation
  As a considered dresser
  I want the local run steps for sign-in written down with the config keys
  So that any developer can start the local identity provider and point the app at it
```

The guide is the single place for run steps and config keys (CLAUDE.md, Layout). The design and the reasons are in [S1-03](S1-03-local-keycloak.md) and [ADR-0010](../adr/0010-identity-provider-keycloak.md). Do not restate them.

Config contract rows to add, with these local values (they must match S1-03.01 and S1-03.02):

- `OIDC_ISSUER_URL`: `http://127.0.0.1:8180/realms/slay-drip`
- `OIDC_JWKS_URL`: `http://127.0.0.1:8180/realms/slay-drip/protocol/openid-connect/certs`
- `OIDC_CLIENT_ID`: `slay-drip-pwa`
- `OIDC_AUDIENCE`: `slay-drip-api`
- `OIDC_REDIRECT_URI`: `http://localhost:5173/auth/callback`
- `KEYCLOAK_BASE_URL`: `http://127.0.0.1:8180`
- `KEYCLOAK_REALM`: `slay-drip`
- `KEYCLOAK_ADMIN_CLIENT_ID`: `slay-drip-backend-admin`
- `KEYCLOAK_ADMIN_CLIENT_SECRET`: throwaway local value in `infra/dev/keycloak/realm/slay-drip-realm.json`, never in an `.env` file

Scaleway column: `OIDC_ISSUER_URL` and `OIDC_JWKS_URL` use `https://<keycloak host>/realms/slay-drip`, with the host set at deploy. The region is one of `fr-par`, `nl-ams` or `pl-waw`, and the host is not decided. `OIDC_CLIENT_ID`, `OIDC_AUDIENCE` and `KEYCLOAK_REALM` are the same values. `OIDC_REDIRECT_URI` is the production PWA origin with the callback path. `KEYCLOAK_ADMIN_CLIENT_SECRET` comes from the container environment and never from source. `OIDC_CLIENT_ID` and `OIDC_REDIRECT_URI` are public configuration and may appear in the client build. The admin secret must not.

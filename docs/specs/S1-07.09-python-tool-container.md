## User story

Requirement served: none names containerised tooling. It enables F7 (through S1-06) and the local-run rule in CLAUDE.md. See the spec's Problem section.

```gherkin
Feature: Python scripts in a container
  As a considered dresser
  I want the S3 and Keycloak smoke scripts to run in a Python container
  So that no Python install is needed on my machine
```

Adds the `python` tool service on a pinned official Python image (3.10 or later, standard library only, per CLAUDE.md). The scripts read their endpoints from the config contract keys, so the compose service passes the in-network values for those same keys. The Keycloak issuer route comes from S1-07.01. Governing design: [S1-07](S1-07-containerised-dev-tooling.md). Spec: [S1-07](S1-07-containerised-dev-tooling.md).

## Acceptance criteria

```gherkin
Scenario: Python scripts run in the Python container
  Given the Python tool service and the local stack running
  When a developer runs the S3 and Keycloak smoke scripts through it
  Then each script runs in the container using only the standard library
  And a passing run ends with its usual OK line
```

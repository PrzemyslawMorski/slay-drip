## User story

Requirement served: none names local stack tooling (gap, see the spec). It enables the local-run rule in CLAUDE.md.

```gherkin
Feature: Parameterise compose, the realm and the throwaway secret
  As a considered dresser
  I want the whole app to run locally in its own worktree
  So that I and the agents can test it end to end without clashes
```

compose.yaml takes its project name and host ports from environment variables set by up.py, with no fixed `name:` or container names and no `.env`. The Keycloak realm gets the web origin and issuer from a template value. The throwaway secret lives in one committed file under infra/dev/ that compose, the S3 config and the smoke scripts read. Governing design: [S1-08](S1-08-local-stack.md), [ADR-0016](../adr/0016-per-worktree-local-stack.md).

## Acceptance criteria

```gherkin
Scenario: No .env file is read
  Given a new worktree with no .env file
  When I run "python scripts/dev/up.py up"
  Then the stack starts and no .env file is read or created
  And every local value comes from compose.yaml or a committed file under infra/dev/
```

## User story

Requirement served: the EU-only processing hard rule (CLAUDE.md, rule 3), so that no local or production identity config points at a region outside the EU.

```gherkin
Feature: EU-only regions in the local identity stack
  As a considered dresser
  I want every region value in the identity stack config checked automatically
  So that my account data stays in the EU, whether the config runs locally or in production
```

Hard-rule test, not a feature scenario. It is kept out of the feature tickets so that it runs first and stays on (TDD-05). The rule is in [CLAUDE.md](../../CLAUDE.md) and [EU-only processing](../code-review/eu-only-processing.md).

## Acceptance criteria

```gherkin
Scenario: The local stack uses only the allowed Scaleway regions
  Given the files compose.yaml, infra/dev/keycloak/realm/slay-drip-realm.json and scripts/dev/keycloak-smoke.sh are present
  When I read every region value and every Scaleway host in those files
  Then every value is one of fr-par, nl-ams or pl-waw
  And no file names any other Scaleway region
```

## Notes

**Agent brief**

- **Role:** `acceptance-author` (see `.claude/skills/tickets-from-spec/references/roles.md`)
- **Goal:** the EU-region hard rule runs as an automated test over the stack config, and it is red until the keycloak files exist.
- **Read first:** [S1-03 Quality and compliance](S1-03-local-keycloak.md#quality-and-compliance), `docs/code-review/eu-only-processing.md`, `docs/code-review/tdd.md`, [ADR-0003](../adr/0003-gherkin-acceptance-tests-with-playwright.md).
- **Files to change:**
  - `frontend/tests/features/hard-rule-eu-region.feature`: the scenario above, verbatim, tagged `@S1-03` and `@hard-rule`.
  - `frontend/tests/steps/hard-rule-eu-region.steps.ts`: the scan. It matches Scaleway hosts (`*.scw.cloud`) and `*_REGION` or `region` keys, then compares the values with the allowed list.
- **Do not touch:** `compose.yaml`, `infra/`, `scripts/dev/`, `docs/`, and the other feature and step files. The scan is read-only. Never read, search, print or create `.env` files.
- **Covers scenarios:** none. This is a hard-rule test; S1-03.01 must pass it.
- **Done when:** `npm run test:acceptance` in `frontend/` runs the scenario. Red: it fails while the keycloak files are missing. Show a failure on a bad value by changing a region value locally, then revert it and record that in the PR. Green: it passes on the real files. `npm run typecheck` and `npm run lint` in `frontend/` show no new errors.
- **Out of scope:** the compose service (S1-03.01). The S3 stand-in's `S3_REGION` default `fr-par` is allowed and is not changed here.
- **Open questions:** None. The Scaleway region for production is an ADR-0010 open item and is not decided by this test. The test allows the three regions in the rule, and it does not pick one.
- **Constraints:** Scan only the three named files, so the test does not depend on other stand-ins. Synthetic data only.

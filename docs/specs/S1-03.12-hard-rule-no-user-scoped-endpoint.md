## User story

Requirement served: the Session 1 scope of S1-03 (no user-scoped endpoint is built here) and F6.1 (account data is only changed through the owner's authenticated request, which a later ticket adds).

```gherkin
Feature: No user-scoped endpoint from the identity stand-in
  As a considered dresser
  I want this spec to add no user-scoped API route
  So that account routes are added only by the sign-up and deletion tickets, with their own tests
```

Hard-rule test, not a feature scenario. The spec's Non-goals rule out user-scoped endpoints. This test is the guard. The rules are in [S1-03 Non-goals](S1-03-local-keycloak.md#non-goals) and [backend ruleset](../code-review/backend-ruleset.md).

## Acceptance criteria

```gherkin
Scenario: The API exposes no user-scoped endpoint for the identity stand-in
  Given the API router built by NewRouter in backend/internal/server
  When I request each user-scoped path in the probe list without a token
  Then each path answers 404 or 405, not a success or an authentication challenge
```

## Notes

**Agent brief**

- **Role:** `backend-engineer` (see `.claude/skills/tickets-from-spec/references/roles.md`)
- **Goal:** the router test proves that the API exposes no user-scoped path for the identity stand-in, and it guards that rule for later tickets.
- **Read first:** [S1-03 Non-goals and Scope](S1-03-local-keycloak.md#non-goals), `docs/code-review/backend-ruleset.md`, `docs/code-review/age-gate.md`, `docs/code-review/consent-and-gdpr.md`, `docs/security.md` sections 5 and 10.
- **Files to change:**
  - `backend/internal/server/server_test.go`: one table-driven test named for the scenario. Its probe list is `GET /me`, `GET /users/me`, `DELETE /users/me`, `GET /account`, `DELETE /account` and `POST /users`. Each must answer 404 or 405 without a token.
- **Do not touch:** `backend/internal/server/server.go` (the router is not changed by this ticket), `backend/internal/db/`, `backend/migrations/`, and any other package. Never read, search, print or create `.env` files.
- **Covers scenarios:** none. This is a hard-rule test. It passes once it is written, because the router has only the health route.
- **Done when:** `go test ./...` in `backend/` passes. `go tool golangci-lint run ./...` in `backend/` shows no new findings. The test has no build tag (BE-24). Red check: temporarily add a `GET /me` route in a local copy, see the test fail, then revert it and record that in the PR.
- **Out of scope:** any user route, sign-up or deletion (later Session 1 and F6 tickets). The local stack and realm (S1-03.01).
- **Open questions:** None.
- **Constraints:** The probe list covers the paths this stack would use. Extending it is part of any PR that adds a route. The test sends no identity and no secret. Synthetic data only.

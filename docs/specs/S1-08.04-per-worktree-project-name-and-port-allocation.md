## User story

Requirement served: none names local stack tooling (gap, see the spec). It enables the local-run rule in CLAUDE.md.

```gherkin
Feature: Per-worktree project name and port allocation
  As a considered dresser
  I want the whole app to run locally in its own worktree
  So that I and the agents can test it end to end without clashes
```

A pure, tested module that turns an absolute worktree path into a compose project name and five host ports (hash block from 20000, probe and shift when a port is taken) and reads and writes `.stack/stack.json`. Governing design: [S1-08](S1-08-local-stack.md), [ADR-0016](../adr/0016-per-worktree-local-stack.md).

## Acceptance criteria

```gherkin
Scenario: Two worktrees run their stacks at the same time without a clash
  Given two worktrees with different paths
  When both stacks are started
  Then each gets its own compose project name and its own ports
  And neither worktree's tests reach the other worktree's services

Scenario: The same worktree path always gets the same project and ports
  Given an absolute worktree path
  When the project name and ports are allocated twice
  Then both results are equal

Scenario: A taken port moves the whole block
  Given the first port of the derived block is in use
  When the ports are allocated
  Then the block shifts and no port is shared with another block
```

## User story

Requirement served: none names local stack tooling (gap, see the spec). It enables the local-run rule in CLAUDE.md.

```gherkin
Feature: Integration tests use the dedicated test database
  As a considered dresser
  I want the whole app to run locally in its own worktree
  So that I and the agents can test it end to end without clashes
```

testenv reads the test database URL and S3 settings from stack.json (or SLAYDRIP_STACK_FILE) and the existing config keys, never the dev database, and fails with a clear message when the stack file is missing. Governing design: [S1-08](S1-08-local-stack.md), [ADR-0016](../adr/0016-per-worktree-local-stack.md).

## Acceptance criteria

```gherkin
Scenario: The test database is fresh and migrated on every run
  Given a row was written to the test database in an earlier run
  When I run "python scripts/dev/up.py up"
  Then the test database "slaydrip_test" exists with every migration applied
  And the earlier row is gone and the dev database is untouched

Scenario: The test environment resolves the test database from the stack file
  Given a stack file with a test database URL
  When the test environment is created
  Then it connects to the test database and not to the dev database

Scenario: A missing stack file stops the integration tests
  Given no stack file
  When the test environment is created
  Then it fails with a message naming the entry script
```

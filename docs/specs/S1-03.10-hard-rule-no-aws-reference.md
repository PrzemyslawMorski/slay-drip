## User story

Requirement served: the Scaleway platform rule (CLAUDE.md, Platform decisions), so that no AWS resource, SDK or CLI enters the identity stack.

```gherkin
Feature: No AWS references in the local identity stack
  As a considered dresser
  I want the identity stack files checked for AWS references automatically
  So that the platform stays on Scaleway, as the team decided
```

Hard-rule test, not a feature scenario. It runs before the build tickets so that it stays on (TDD-05). The rule is in [CLAUDE.md](../../CLAUDE.md).

## Acceptance criteria

```gherkin
Scenario: The local stack references no AWS resource, SDK or CLI
  Given compose.yaml, the infra/dev/keycloak folder, scripts/dev/keycloak_smoke.py and docs/local-development.md are present
  When I search them for AWS resource, SDK or CLI references
  Then none of them contains "amazonaws", "aws-sdk", "awscli", "aws cli" or "AWS_"
```

## Notes

**Agent brief**

- **Role:** `acceptance-author` (see `.claude/skills/tickets-from-spec/references/roles.md`)
- **Goal:** the no-AWS hard rule runs as an automated search over the identity stack files, and it is red until those files exist.
- **Read first:** [S1-03 Quality and compliance](S1-03-local-keycloak.md#quality-and-compliance), [CLAUDE.md](../../CLAUDE.md) (Platform decisions), `docs/code-review/tdd.md`, [ADR-0003](../adr/0003-gherkin-acceptance-tests-with-playwright.md).
- **Files to change:**
  - `frontend/tests/features/hard-rule-no-aws.feature`: the scenario above, verbatim, tagged `@S1-03` and `@hard-rule`.
  - `frontend/tests/steps/hard-rule-no-aws.steps.ts`: the case-insensitive search over the four named paths, folders read recursively.
- **Do not touch:** `compose.yaml`, `infra/`, `scripts/dev/`, `docs/`, `scripts/dev/s3_smoke.py` (outside this scan), and the other feature and step files. Never read, search, print or create `.env` files.
- **Covers scenarios:** none. This is a hard-rule test; S1-03.01, S1-03.02 and S1-03.03 must pass it.
- **Done when:** `npm run test:acceptance` in `frontend/` runs the scenario. Red: it fails while the keycloak files are missing. Show a failure by adding one forbidden token to a local copy, then revert it and record that in the PR. Green: it passes on the real files. `npm run typecheck` and `npm run lint` in `frontend/` show no new errors.
- **Out of scope:** the stack, smoke and docs content (S1-03.01 to S1-03.03). The existing S3 stand-in is not scanned, because its `--aws-sigv4` option is the S3 signing protocol name, not an AWS dependency (see the spec's Risks table).
- **Open questions:** None.
- **Constraints:** The search covers only the named paths. A match stops the ticket and is reported to the user, not edited away. Synthetic data only.

## User story

```gherkin
Feature: Tokens carry the API resource as their audience
  As a considered dresser
  I want my sign-in token to name the API it is for
  So that the API and the MCP endpoint accept only tokens issued for them
```

Context: ADR-0012 sets the API's audience to its canonical URI, replacing `slay-drip-api`, so that tokens are bound to the resource as RFC 8707 requires. The local realm must issue tokens with that audience, using the same config key as production.

## Acceptance criteria

```gherkin
Scenario: A request without a valid token is refused
  Given no token, an expired token, or a token for another audience
  When the client calls any MCP tool
  Then the call returns 401 with a WWW-Authenticate header and no detail about why it failed
```

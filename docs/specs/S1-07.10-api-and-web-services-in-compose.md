## User story

Requirement served: none names containerised tooling. It enables F7 (through S1-06) and the local-run rule in CLAUDE.md. See the spec's Problem section.

```gherkin
Feature: API and frontend run from compose
  As a considered dresser
  I want `docker compose up api web` to start the app against the local stack
  So that I can use and test the app with only Docker installed
```

Adds the `api` service (the Go image, `go run ./cmd/api`) and the `web` service (the Node image, the Vite dev server bound so the browser can reach it). Both read the stand-ins through the config contract keys with no key added for containers. Local values may differ only where a hostname changes inside the network. No `.env` file or `env_file` pointing to one. Governing design: [S1-07](S1-07-containerised-dev-tooling.md), [ADR-0005](../adr/0005-local-cloud-emulation.md). Spec: [S1-07](S1-07-containerised-dev-tooling.md).

## Acceptance criteria

```gherkin
Scenario: The API and frontend run from compose
  Given the compose file
  When a developer starts the "api" and "web" services
  Then the API answers GET /healthz on 127.0.0.1:8080 and the frontend is served on localhost:5173
  And both reach the stand-ins through the same config keys as production

Scenario: No .env file is read
  Given the tool and app services in compose
  When their definitions are inspected
  Then none reads a ".env" file, an "--env-file" option or an "env_file" that points to one
  And every local value comes from the compose file or a committed file under infra/dev/

Scenario: The local stack keeps the production config keys
  Given the services running in containers
  When their environment is listed
  Then every key is a name in the config contract of docs/local-development.md
  And no key exists only for the containerised run
```

## Notes

**Agent brief**

- **Role:** `infra-engineer` (see `.claude/skills/tickets-from-spec/references/roles.md`)
- **Goal:** `docker compose up api web` serves the API on `127.0.0.1:8080` and the frontend on `localhost:5173`, both wired to PostgreSQL, S3 and Keycloak by the production config keys.
- **Read first:** [local development guide](../local-development.md) (config contract), [ADR-0005](../adr/0005-local-cloud-emulation.md), [ADR-0010](../adr/0010-identity-provider-keycloak.md), the S1-07.01 discovery note
- **Files to change:**
  - `compose.yaml`, the `api` and `web` services, ports bound to `127.0.0.1`, health checks, dependencies on the stand-ins
  - `infra/dev/app.config`, committed throwaway local values, only if the values do not fit inline in `compose.yaml`
- **Do not touch:** `backend/`, `frontend/` (including `vite.config.ts`: pass host and polling options on the command line or by environment), the tool services, `docs/local-development.md`. Never read, search, print or create `.env` files.
- **Covers scenarios:** `The API and frontend run from compose`; `No .env file is read`; `The local stack keeps the production config keys`
- **Done when:** the three scenarios pass by reading `compose.yaml`, and a live run passes: `docker compose up -d api web`, then `GET /healthz` on `127.0.0.1:8080` returns `{"status":"ok"}` and `localhost:5173` serves the app. The PR shows the run and the environment key list compared with the config contract.
- **Out of scope:** Playwright run (S1-07.08), CI (S1-07.11), docs (S1-07.13).
- **Open questions:** None.

Definition of done note: no AI, consent, retention or body data is touched, and no UI is changed, so those two lines do not apply.

If Vite 8 needs a config change for polling or host binding that cannot be done from the command line, stop and report: `frontend/vite.config.ts` has no owning role.

## User story

Requirement served: the test data hard rule (CLAUDE.md, rule "Test data") and the 18+ and no-identification rules, so that the realm and the smoke fixtures never hold a real person's data.

```gherkin
Feature: Synthetic personas only in the local identity realm
  As a considered dresser
  I want the realm and the smoke fixtures checked for real personal data automatically
  So that no real person's account or attribute can enter the repo through the local stack
```

Hard-rule test, not a feature scenario. The manual review of the same rule is in S1-03.04. This ticket is the automated guard. The rule is in [S1-03 Quality and compliance](S1-03-local-keycloak.md#quality-and-compliance) and [security guide](../security.md).

## Acceptance criteria

```gherkin
Scenario: The realm and smoke fixtures hold only synthetic personas
  Given the committed realm file is infra/dev/keycloak/realm/slay-drip-realm.json
  And the smoke script is scripts/dev/keycloak_smoke.py
  When I review the realm users, their attributes, the client settings and the users the smoke script creates
  Then the realm users are exactly persona.menswear@example.test, persona.womenswear@example.test and smoke.user@example.test
  And no user has an attribute for age, date of birth, postal address, body, measurement or special category
  And the public client slay-drip-pwa has publicClient set to true and no client secret
  And the smoke script creates throwaway users only on example.test
```

Show a failure by adding one non-synthetic user to a local copy of the realm, then revert it and record that in the PR. Green: it passes on the real files. `npm run typecheck` and `npm run lint` in `frontend/` show no new errors.
- **Out of scope:** the realm and smoke content (S1-03.01 and S1-03.02). The review of the same rule (S1-03.04). Sign-up and the 18+ gate (later Session 1 tickets).

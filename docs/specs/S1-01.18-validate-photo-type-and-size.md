## User story

Requirement served: F2.2 single-item capture and the wardrobe view that follows it, with no account (spec [S1-01](S1-01-anonymous-wardrobe-upload.md)).

```gherkin
Feature: Validate photo type and size before storing
  As a considered dresser
  I want the anonymous wardrobe behaviour in S1-01
  So that this ticket's scenarios can be checked against the spec
```

Frontend only. Photos stay on the device under [ADR-0004](../adr/0004-on-device-wardrobe-storage.md).

## Acceptance criteria

```gherkin
Scenario: A file that is not a photo is rejected even when it is named as one
  Given I have confirmed that I am 18 or over
  And I have agreed to store photos of my clothes on this device
  When I add a file named "receipt.jpg" that is not a JPEG, PNG or WebP image
  Then I see an error that the file is not a supported photo
  And my wardrobe is empty

Scenario: A photo larger than 10 MB is rejected
  Given I have confirmed that I am 18 or over
  And I have agreed to store photos of my clothes on this device
  When I add a JPEG photo that is larger than 10 MB
  Then I see an error that the photo is too large
  And my wardrobe is empty
```

## Notes

**Agent brief**

- **Role:** `frontend-engineer` (see `.claude/skills/tickets-from-spec/references/roles.md`)
- **Goal:** A pure check: accept only JPEG, PNG or WebP by content, not by file name, and reject any file over 10 MB.
- **Read first:** [frontend ruleset](../../docs/code-review/frontend-ruleset.md), [product guardrails](../../docs/code-review/product-guardrails.md), [TDD](../../docs/code-review/tdd.md)
- **Files to change:**
  - `frontend/src/photos/validatePhoto.ts`, what changes in it
  - `frontend/src/photos/validatePhoto.test.ts`, what changes in it
- **Do not touch:** anything outside the role's owned paths, and the files the neighbouring tickets change.
- **Covers scenarios:** `A file that is not a photo is rejected even when it is named as one`; `A photo larger than 10 MB is rejected`
- **Done when:** `npm run test:unit` and `npm run typecheck` in `frontend/`, then `npm run test:acceptance` for the two rejection scenarios.
- **Out of scope:** The add flow that calls this is S1-01.21.
- **Open questions:** None.

Unit-level tests cover the magic bytes of each format, a file named .jpg that is not an image, and the 10 MB boundary.

## User story

Requirement served: none names containerised tooling. It enables F7 (through S1-06) and the local-run rule in CLAUDE.md. See the spec's Problem section.

```gherkin
Feature: Containerised tooling is reviewed for secrets and supply chain
  As a considered dresser
  I want the tooling checked for secrets, mounts and image provenance
  So that nothing sensitive leaves the machine or enters the repo
```

Read-only review. No personal data is in scope (no DPO review needed, ADR-0014). The review checks that no Docker socket is mounted into any tool container (owner decision, 2026-11-02), host mounts, image pinning and provenance (`docs/security.md` section 12), that no `.env` file or secret is referenced, that no AWS reference appears (CLAUDE.md) and that synthetic data is the only data. Spec: [S1-07](S1-07-containerised-dev-tooling.md).

## Acceptance criteria

```gherkin
Scenario: No .env file is read
  Given the tool and app services in compose
  When their definitions are inspected
  Then none reads a ".env" file, an "--env-file" option or an "env_file" that points to one
  And every local value comes from the compose file or a committed file under infra/dev/
```

## User story

Requirement served: none names containerised tooling. It enables F7 (through S1-06) and the local-run rule in CLAUDE.md. See the spec's Problem section.

```gherkin
Feature: Stack acceptance scenarios check a stack that is already running
  As a considered dresser
  I want the local identity provider scenarios to check the running stack instead of starting it
  So that the whole acceptance suite can run in the Playwright container without a Docker socket
```

The owner decided on 2026-11-02 that the stack-lifecycle scenarios are rewritten to check a stack that is already running. The host starts the stack with one command, and the tests only check that it answers. See the spec change note in [S1-07](S1-07-containerised-dev-tooling.md#design) for the wording before and after. The S1-03 scenarios are not edited in the S1-03 spec; its note says they are being rewritten here. Spec: [S1-07](S1-07-containerised-dev-tooling.md).

## Acceptance criteria

```gherkin
Scenario: The local identity provider starts beside PostgreSQL and the S3 stand-in
  Given the local stack was started on the host with "docker compose up -d"
  When I check the running services
  Then the keycloak service is running and reports healthy
  And keycloak listens on 127.0.0.1 only
  And the database and object-storage services are still running
  And keycloak has no named volume
```

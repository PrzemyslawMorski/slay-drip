## User story

Requirement served: none names local stack tooling (gap, see the spec). It enables the local-run rule in CLAUDE.md.

```gherkin
Feature: Vite proxies /api and takes its port from the stack file
  As a considered dresser
  I want the whole app to run locally in its own worktree
  So that I and the agents can test it end to end without clashes
```

Vite reads the web and API ports from stack.json (or SLAYDRIP_STACK_FILE), proxies `/api` to the API, keeps strictPort, and the app calls a relative API base so the browser needs no CORS. VITE_* defaults stay for production builds. Governing design: [S1-08](S1-08-local-stack.md), [ADR-0016](../adr/0016-per-worktree-local-stack.md).

## Acceptance criteria

```gherkin
Scenario: Two worktrees run their stacks at the same time without a clash
  Given two worktrees with different paths
  When both stacks are started
  Then each gets its own compose project name and its own ports
  And neither worktree's tests reach the other worktree's services

Scenario: The dev server proxies /api to this worktree's API
  Given a stack file with the API port of this worktree
  When the browser requests /api/healthz from the dev server
  Then the response comes from that API port without a CORS header being needed
```
